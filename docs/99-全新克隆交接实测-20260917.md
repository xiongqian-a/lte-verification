## 4. 这次实测证明了什么

- 新目录 clone 后不需要修改任何项目路径。
- 不需要执行 `pip install`。
- 不需要启动 eNB、EPC、IMS 或仪表。
- `bootstrap.cmd --colleague-replay` 可以复跑已经提交的本机证据。
- 固定 commit 校验、统一 runner、TC-011 自检和 TC-011 不变量全部通过。
- `standards/official/` 中当前套件直接引用的原文和 RFC 可以通过 SHA256 校验。
- 从 clone 到同事复跑完成，本次实测约 36.81 秒；完整便携性检查约 37.59 秒。

## 5. 这次实测没有证明什么

- 没有重新连接真实 eNB、EPC、IMS、HSS 或 SS。
- 没有重新产生一套新的现场日志。
- 没有产生 `36.523-1`、`34.229-1` 或第三方入网 Verdict。
- 没有替代 `OFFICIAL_VERDICT: null` 的边界。

## 6. 10 分钟承诺的前提

在以下条件满足时，当前仓库可以在 10 分钟内完成一次全新 clone 和一键复跑：

1. 同事有仓库读取权限；
2. 同事本机有 Git；
3. 同事有 Python 3.10+，或者系统允许 bootstrap 自动安装 Python；
4. 网络可以访问 GitHub，自动安装 Python 时还可以访问对应软件源；
5. 复跑目标是仓库中已经提交的证据，不是重新搭建核心网或重新执行现场测试。

如果缺少仓库权限、Git、Python 安装权限或网络，脚本不能凭空完成这些外部条件。

## 7. 交接时的正确表述

可以说：

> 仓库已在全新目录通过 clone 和一键复跑验证，约 37 秒重现已提交的本地验证结果。
> 该复跑不依赖原工作区路径，不需要安装项目依赖，也不需要启动核心网或 IMS。

不能这样说：

> 同事在这台机器上完成了新的 eNB/EPC/IMS 端到端测试。

也不能这样说：

> 这次全新 clone 复跑已经通过官方 36.523-1 或 34.229-1 一致性。
