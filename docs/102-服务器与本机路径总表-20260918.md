## 3. 证据完整性口径

### 3.1 作为“当前仓库黄金证据快照”的完整性

从交接基线角度，`evidence/` 中已经提交的文件是完整的。统一 runner 能读取这些
文件的哈希、结构和 checker 输入，并得到固定的本地复跑结果。它们可以证明：

- 仓库中的 checker 能读取对应原始日志或抓包；
- 当前提交的本地行为结果可重复；
- 受限项没有被脚本静默升级成官方 PASS。

### 3.2 作为“34 条功能 TC 全部有独立原始证据”的完整性

不完整。当前 34 条中有 14 条没有仓库内独立可复跑证据或独立 checker：

| TC | 当前状态 | 原因 |
|---|---|---|
| TC-002、TC-003 | `STANDARD_ALIGNED` | 缺真实 EPC 触发专用承载建立或释放 |
| TC-006、TC-007、TC-008、TC-009、TC-010 | `STANDARD_ALIGNED` | 缺真实 eNB/RAN/EPC 或合格 SS 观测 |

### 3.3 作为“官方一致性证据”的完整性

不完整，而且不能靠仓库补成完整。官方 Verdict 必须由合格 SS、仪表或检测机构
按对应官方 TP 执行。仓库里的 `LOCAL_PASS`、`LIMITED_PASS`、`SELFCHECK_PASS`
和 `STANDARD_ALIGNED` 都不能改名为 `OFFICIAL_PASS`。
