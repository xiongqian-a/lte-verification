## 1. 用例执行卡（目的、前置条件、验证流程、TP Verdict）

【用例ID】TC-032 IMS 错误码 503 / 504
【来源】TS 34.229-1 V14.7.0：`10.1 Invalid Behaviour - 503 Service Unavailable`（行 5741-5809）、`12.2 MO Call - 503 Service Unavailable`（行 6060-6118）、`12.2a MO Call - 504 Server Time-out`（行 6119-6186），主口径为 `34229-1e70-word.txt`。
【测试目的】验证 UE 收到 503（带 Retry-After=T）时不自动重试到 T 到期；收到特定 504 restoration body 时执行 initial registration。
【优先级】P0
【前置条件/SS 环境】
1. UE 已完成 IMS 注册（官方前置：Annex C.2 或 C.2a 到 last step）。
2. SS 配置 IMS AKA 共享密钥，已完成 AKAv1-MD5 鉴权并接受注册。
3. 504 场景：SS 能按 24.229 clause 5.1.2A.1.6 构造 P-Asserted-Identity 与 `application/3gpp-ims+xml` alternative-service body。
【测试步骤】
- 503 INVITE：UE 按 TS 36.508 table 4.5A.6.3-1 / Annex C.21 发起 MO call；SS 回 503（Retry-After=T）；UE 回 ACK；SS 等 T，检查 UE 不重发 INVITE；T 后允许重试。
- 504 INVITE：UE 按 TS 36.508 table 4.5A.6.3-1 / Annex C.21 发起 MO call；SS 回 504（Annex A.4.6，body 按 A.2.7）；UE 回 ACK；UE 按 Annex C.2 步骤 4-11 执行 initial registration。
【预期判据】
- 503：SS 在收到 ACK 后、T 到期前未再收到 INVITE；T 后才允许重试。
- 504：SS 检查 UE 发起 initial registration，完成 restoration；未发起则失败。
【通过标准】官方 34.229-1 TP Verdict 判定：503 核心是 Retry-After 约束，504 核心是 restoration initial registration。
【失败处理】记录失败步骤、抓包文件、UE 日志，关联缺陷 ID；本地单测只记录研发行为证据，不做官方 Verdict。

## 2. 官方骨架 / 官方 TP 原文摘录（行号级）

### 2.1 503 SUBSCRIBE（10.1 相关）

- 官方标题：`10.1 Invalid Behaviour - 503 Service Unavailable`，行 5741。
- Conformance requirement（行 5745-5748）：UE 收到初始 SUBSCRIBE 的 503 且含 Retry-After，不得在 Retry-After 指示的时间前自动重试。
- 步骤要点（行 5756-5760）：
  1. UE 在已有安全关联上发 SUBSCRIBE。
  2. SS 回 503，Retry-After=T。
  3. SS 等待 T，检查 UE 此期间不重试。
  4. UE 在 T 后发新 SUBSCRIBE。
- Verdict 点：行 5808-5809：SS 等待期间 UE 不得 re-attempt；T 后重发 SUBSCRIBE。

### 2.2 503 MO Call

- 官方标题：`12.2 MO Call - 503 Service Unavailable`，行 6060。
- Conformance requirement（行 6063-6066）：originating UE 收到 initial INVITE 的 503 且含 Retry-After，不得自动重试到 Retry-After 指示的时间后。
- 步骤要点（行 6075-6079）：
  1. UE 按 TS 36.508 table 4.5A.6.3-1 steps 1-8 发起 MTSI MO speech call。
  2. SS 回 503，Retry-After=T。
  3. UE 回 ACK。
  4. SS 等待 T，检查 UE 不重发 INVITE。
- Verdict 点（行 6117-6118）：step 6 UE 不得在 SS 收到 ACK 后 T 时间内重发 INVITE。

### 2.3 504 MO Call

- 官方标题：`12.2a MO Call - 504 Server Time-out`，行 6119。
- Conformance requirement（行 6122-6135）：504 含 P-Asserted-Identity（来自 Service-Route/Path）且含 `application/3gpp-ims+xml` alternative-service 的 `restoration` / `initial-registration`，UE 应执行 initial registration。
- 步骤要点（行 6143-6146）：
  1. UE 按 TS 36.508 table 4.5A.6.3-1 步骤 1-8 发起 MO call。
  2. SS 回 504（Annex A.4.6；body 按 A.2.7）。
  3. UE 回 ACK。
  4. UE 按 Annex C.2 步骤 4-11 执行 initial registration。
- Verdict 点（行 6186）：step 3 后 UE 必须执行 initial registration。
