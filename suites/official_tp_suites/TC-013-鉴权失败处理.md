## 0. 执行卡

【用例ID】TC-013 / 34.229-1 Invalid Behaviour（MAC Parameter Invalid / SQN out of range）

【来源】3GPP TS 34.229-1（本地抽取文件：`_extract/34229-1e70_ascii.txt`），Invalid Behaviour 两段；关联 `TS 24.229` 5.1.1.5.1 / 5.1.1.5.3，`TS 33.203`，`TS 33.102`，Annex C.2。

【测试目的】验证 UE 收到无效 AKA 挑战（MAC Parameter Invalid 或 SQN out of range）时，能按 3GPP 要求做二次 REGISTER 无效指示（不带/带 auts、更新 Security-Client、不建临时 SA），并在随后有效 challenge 下完成注册。

【优先级】P0

【前置条件/SS环境】
1. UE 已完成 P-CSCF 发现，具备 initial REGISTER 条件。
2. SS/IMS 测试台能构造并发出 MAC invalid 或 SQN out of range 的 401 AKA challenge。
3. 本地真实 bad-key 日志只能证明错钥被拒，不能证明 UE 按官方无效挑战语义发二次 REGISTER；该部分继续标受限。

【测试步骤】
1. UE 发送 initial REGISTER。
2. SS 回 401，AUTN 中 MAC invalid 或 SQN out of range（SQN 场景 AMF 置 AMF_RESYNCH）。
3. UE 发第二个 REGISTER：
   - MAC invalid：不带 `auts`，`response` 为空，不建临时 SA，更新 Security-Client / 新 SPI/port；
   - SQN out of range：带 `auts`，更新 Security-Client / 新 SPI/port，不建临时 SA。
4. SS 回有效 401（SQN 场景 SS 先回有效 401，再等 UE 在临时 SA 上发带正确 response 的 REGISTER）。
5. 完成稳定注册（200 OK + SUBSCRIBE + NOTIFY）。

【预期判据（逐消息检查）】
- MAC invalid：第二、三次 REGISTER 的 `Authorization.response` 为空，且不含 `auts`；`Security-Client` 含新 spi_uc/spi_us/port_uc；不建立临时 SA。
- SQN out of range：第二次 REGISTER 含 `auts`（值不需校验）；后续有效 401 后 REGISTER 使用临时 SA，携带正确 response。
- 最终能完成注册、不崩溃、不无限 401。

【通过标准】所有步骤和字段检查通过，UE 最终进入已注册状态；本地自检 PASS 不等于官方 Invalid Behaviour Verdict。

【失败处理】记录失败步骤、401 类型、第二次 REGISTER 头部、抓包与 UE 日志，关联缺陷 ID；正式一致性需一致性测试仪注入官方无效 AKA 向量。

### 场景 A：MAC Parameter Invalid（L4253-4321）

- 标题/目的（L4253-4254）：`Invalid Behaviour ? MAC Parameter Invalid`；`To test that the UE when receiving a 401 (Unauthorized) response with an invalid MAC value to its initial REGISTER request behaves correctly.`
- Conformance requirement（L4262-4269 / L4270-4275）：
  `If, in a 401 (Unauthorized) response, either the MAC or SQN is incorrect the UE shall respond with a further REGISTER indicating to the S-CSCF that the challenge has been deemed invalid as follows: in the case where the UE deems the MAC parameter to be invalid the subsequent REGISTER request shall contain no "auts" Authorization header field parameter and an empty "response" Authorization header field parameter ...; whenever the UE detects any of the above cases, the UE shall ... populate a new Security-Client header field ... shall contain new values for spi_uc, spi_us and port_uc; and not create a temporary set of security associations.`
- Test procedure / Expected sequence（L4278-4296）：`SS responds to the initial REGISTER request with an invalid 401 Unauthorized response ... except that the MAC value in AUTN should be incorrect`；`SS waits for the UE to send a second Registration message indicating that the received 401 Unauthorized message was invalid`；`SS sends an invalid 401 Unauthorized message, same as in step 2)`；`SS waits for the UE to send a third Registration message ...`；`SS completes the registration procedure ...`.
- Specific message contents（L4301-4321）：REGISTER 默认 Annex A.1.1 condition A1；401 默认 Annex A.1.2 且 MAC 错误；REGISTER steps 3/5 含 incremented CSeq、同 Call-ID、空 response、无 auts、新 SPI/新 protected client port；SS 检查 UE 不用安全关联、不建临时 SA。

### 场景 B：SQN out of range（L4322-4392）

- 标题/目的（L4322-4324）：`Invalid Behaviour ? SQN out of range`；`To test that the UE when receiving a 401 (Unauthorized) response with SQN out of range to its initial REGISTER request behaves correctly.`
- Conformance requirement（L4332-4339 / L4340-4346）：`in the case where the UE deems the SQN to be out of range, the subsequent REGISTER request shall contain the "auts" Authorization header field parameter`；后续验证 UE 在有效 401 下能完成鉴权注册。
- Test procedure / Expected sequence（L4349-4366）：`SS responds ... with an invalid 401 Unauthorized response ... except that the SQN value in AUTN should be out of range`；`SS waits for the UE to send a second Registration message indicating that the received 401 Unauthorized message was invalid`；`SS sends a valid 401 Unauthorized message`；`SS waits for the UE to send a Registration request using the temporary set of security associations ... with valid answer`.
- Specific message contents（L4367-4392）：REGISTER 默认 Annex A.1.1 condition A1；401 默认 Annex A.1.2，AUTN 含 SQN out of range 且 AMF 置 AMF_RESYNCH；REGISTER 第二步含 `auts= ?auts-value?, auts-value not to be checked`、新 SPI/新 protected client port；SS 检查不含临时 SA、带 auts、新 Security-Client。

## 1. 目的 / 为什么

验证 UE 在收到无效 AKA 挑战（MAC Parameter Invalid 或 SQN out of range）时，能按 3GPP 要求做二次 REGISTER 动作，而不是把这当正常 challenge 应答。

## 2. 官方骨架

- 来源：`34.229-1` Invalid Behaviour。
- 文本抽取记录：`_extract/34229-1e70_ascii.txt`，MAC 无效行 4253，步骤行 4254-4296；SQN 越界行 4322，步骤行 4323-4367。

### 场景 A：MAC Parameter Invalid

1. SS 对 initial REGISTER 回 401，AUTN 中 MAC 错误。
2. UE 再次 REGISTER：
   - 不带 `auts`；
   - `response` 为空；
   - 更新 Security-Client / 新 SPI/port；
   - 不建临时 SA。
3. SS 再回同款无效 401。
4. UE 第三次 REGISTER 仍满足上述规则。
5. SS 用有效 challenge 完成稳定注册。

### 场景 B：SQN out of range

1. SS 回 401，AUTN 中 SQN 越界，AMF 设为 AMF_RESYNCH。
2. UE 识别越界，再次 REGISTER 带 `auts`，更新 Security-Client / 新 SPI/port，不建 SA。
3. SS 回有效 401。
4. UE 在临时 SA 上发 REGISTER 带正确 response。
5. 完成稳定注册。

## 3. 前置条件

- UE 已完成 P-CSCF 发现，具备初始 REGISTER 条件。
- SS/IMS 测试台能构造并发出 `MAC invalid` 或 `SQN out of range` 的 401 AKA 挑战。
- 当前本地测试台能做到“错误密钥被拒”，但还不能完全模拟官方 Invalid Behaviour 后 UE 应执行的二次 REGISTER 语义。

## 4. 验证流程

1. 抓取包含无效挑战 401 的 REGISTER 会话日志。
2. 判定第二次 REGISTER 是否：
   - `response` 为空（MAC invalid 场景）；
   - 不带 `auts`（MAC invalid 场景）；
   - 带 `auts`（SQN out of range 场景）；
   - 更新 `Security-Client` / SPI / port；
   - 不建立临时 SA（无效 MAC）。
3. 继续观察后续有效挑战后 UE 是否能完成稳定注册。

## 5. TP Verdict 判据

- UE 能区分 MAC 无效与 SQN 越界，按对应要求重发 REGISTER。
- 不建立被错误挑战影响的临 SA/不应答错误 challenge。
- 最终能用正确 challenge 完成注册，不崩溃、不无限 401。
